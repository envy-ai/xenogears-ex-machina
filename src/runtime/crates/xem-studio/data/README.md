# Public field opcode metadata

`field-opcodes.json` is generated by `tools/studio/field_opcodes.py` from the
independently authored `tools/analysis/events.py` tables and supporting constants.
The opcode facts were recovered from the matching field interpreter; their
analysis provenance and limits are in `docs/scripts/field-events.md`.
The generator preserves every form's mnemonic, handler, size, flow, operands,
effect, selector, alternative/inner advances and setup relation. Operand widths,
flow names, comparison names, prefix facts and loader slack accompany them.

This is authored-tool-generated public analysis metadata under the repository
MIT licence. It contains no game component bytes, original assembly, extracted
assets or local sweep results. It belongs in `packaging/source-files.txt` as
public UTF-8 JSON; private map data and oracle output remain ignored.
The embedded source SHA-256 identifies the authoritative Python source, not a
private input. Regenerate with `python3 -m tools.studio.field_opcodes`; verify
with `--check` and `tests/test_studio_field_opcodes.py` in the pinned shell.
Never hand-edit opcode forms here or maintain a second Rust opcode registry.

## Operand access facts (milestone three)

`field-access.json` is generated by `python3 -m tools.studio.field_access`
(`--check` verifies freshness). It joins the existing opcode operand descriptors
with explicit accesses in the recovered C interpreter and its reader/screen
helpers. `tools/analysis/event_access.py` is the single source-analysis recipe;
it does not define another opcode table. The JSON records the exact source file
hashes and each proof's function, function hash and helper. It is public,
MIT-licensed analysis metadata containing no game bytes.

These are **possible explicit operand accesses**, including conditional helper
calls. They are not a simulation, execution order, implicit-state inventory or
proof that a conditional access executes. Read/write roles require a proven
helper or checked delegation; unresolved and indirect descriptors retain a
reason and are excluded from concrete dependencies. The current five unknown
facts include two data-array addresses and three cross-PC/continuation cases.
Regenerate after changing any recorded source, and inspect role changes rather
than filling gaps from mnemonic names. The milestone-two opcode JSON and graph
schema remain unchanged.

## Field model dispatch facts (milestone seven)

`field-models.json` is generated by `python3 -m tools.studio.model_formats`
from the existing `tools.analysis.dispatch_tables.primitive_table` reader of
`src/decomp/src/resident/model_renderer.c`. It records source hashes, draw and
prepare function names, record/auxiliary/packet strides and recognized texture
override control codes. These are public authored-source analysis facts, not
game component bytes or a copied third-party registry. The repository MIT
licence applies. Verify freshness with `--check` and
`tests/test_studio_model_formats.py`; do not hand-maintain another Rust table.
Original field meshes use group-relative offsets and an overlapping SpriteModel
view at group+0x10; standalone sprite-model relocation uses a different base.
This metadata alone is not a geometry decoder or completed M7 acceptance.
